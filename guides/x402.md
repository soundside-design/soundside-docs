# x402: Pay-Per-Call with Crypto

x402 lets any agent call Soundside tools by paying with USDC on Base. No API key, no account, no signup.

## What You Need

- **`WALLET_PRIVATE_KEY`** — a hex private key (0x-prefixed) for any EVM wallet
- **USDC on Base mainnet** (chain ID 8453) in that wallet
- **Python ≥ 3.10**

**That's it.** You do NOT need:
- ❌ A Soundside account or signup
- ❌ An API key
- ❌ `CDP_API_KEY` — that is a *server-side* credential used by Soundside's payment facilitator; clients never touch it

## How It Works

1. Agent sends a `tools/call` request to `https://mcp.soundside.ai/mcp`
2. If no valid payment is included, Soundside returns **HTTP 402** with payment requirements
3. Agent signs an EIP-3009 authorization (off-chain, no gas)
4. Agent re-sends the request with the `payment-signature` header
5. Soundside executes the tool and returns the result — **including the resource URL directly in the response**

## Quick Start — Python (Recommended)

**Do NOT hand-roll the `payment-signature` header.** The encoding is non-trivial (EIP-712 typed data + base64 envelope). Use the x402 SDK.

### Sync Example (simplest — works in agents and scripts)

```python
import json, os, requests
from eth_account import Account
from x402 import x402ClientSync
from x402.mechanisms.evm.exact import register_exact_evm_client
from x402.mechanisms.evm.signers import EthAccountSigner
from x402.schemas import PaymentRequired
from x402.http import encode_payment_signature_header, X_PAYMENT_HEADER

ENDPOINT = "https://mcp.soundside.ai/mcp"

account = Account.from_key(os.environ["WALLET_PRIVATE_KEY"])  # 0x-prefixed hex
signer  = EthAccountSigner(account)

payment_client = x402ClientSync()
register_exact_evm_client(payment_client, signer)

def call_tool(tool: str, args: dict, timeout: int = 60) -> dict:
    """Call an MCP tool, paying any 402 challenge automatically."""
    session = requests.Session()

    # 1. Initialize MCP session
    init_r = session.post(ENDPOINT, json={
        "jsonrpc": "2.0", "id": "1", "method": "initialize",
        "params": {"protocolVersion": "2025-11-25", "capabilities": {},
                   "clientInfo": {"name": "my-agent", "version": "1.0"}},
    }, headers={"Content-Type": "application/json",
                "Accept": "application/json, text/event-stream"})
    session_id = init_r.headers.get("mcp-session-id", "")

    headers = {
        "Content-Type": "application/json",
        "Accept": "application/json, text/event-stream",
        "mcp-session-id": session_id,
        "x402-wallet": account.address,  # required for x402 identity
    }
    payload = {"jsonrpc": "2.0", "id": "2", "method": "tools/call",
               "params": {"name": tool, "arguments": args}}

    # 2. First attempt — expect 402
    r = session.post(ENDPOINT, json=payload, headers=headers, timeout=timeout)

    if r.status_code == 402:
        # 3. Parse payment requirements from 402 body
        pr = PaymentRequired.model_validate(r.json())

        # 4. Sign (off-chain EIP-712, no gas) and encode header
        payment_payload = payment_client.create_payment_payload(pr)
        payment_header  = encode_payment_signature_header(payment_payload)

        # 5. Retry with payment
        r = session.post(ENDPOINT, json=payload,
                         headers={**headers, X_PAYMENT_HEADER: payment_header},
                         timeout=timeout)

    # 6. Parse SSE response
    for line in r.text.splitlines():
        if line.startswith("data:"):
            obj = json.loads(line[5:])
            if "result" in obj:
                content = obj["result"].get("content", [{}])
                return json.loads(content[0].get("text", "{}"))
    return {}

# Generate text — ~$0.01 USDC
result = call_tool("create_text", {"provider": "vertex",
                                   "prompt": "Write a haiku about Base blockchain."})
print(result)

# Generate image — ~$0.04 USDC
result = call_tool("create_image", {"provider": "minimax",
                                    "prompt": "A futuristic city at sunset"}, timeout=120)
print(result.get("resource_id"))
print(result.get("wallet_link"))   # share with a human to view in browser
```

> **Key points:**
> - Always include `"x402-wallet": account.address` header — the server uses it to assign resources to your wallet's project
> - The `PaymentRequired` object comes from the **body** of the 402 response (not a header)
> - Use `x402ClientSync` + `create_payment_payload()` — do not construct the payment dict manually
> - Each call needs a fresh MCP session (`mcp-session-id`) — sessions do not persist across calls

## Pricing Philosophy

Soundside aims to break even on provider pass-through costs with a minimal margin (~10%). Editing and library tools are $0.01/call. Analysis (`analyze_media`) is priced per mode: $0.01 for `technical` and `export_edl`, $0.02 for `transcribe` and `detect_segments`, and $0.03 for `vision_qa`. The real value is in the platform — not markup on provider APIs.

All 15 public tools across all providers are enabled on x402. Check `/api/x402/status` for the current full list.

## Resource Retrieval — No Second Call Needed

**After a successful tool call, the resource URL is returned directly in `structuredContent.url`.** You do NOT need to call a separate retrieval tool — the image/video/audio URL is in the same response that confirms generation.

```json
{
  "result": {
    "structuredContent": {
      "resource_id": "abc-123",
      "url": "https://storage.googleapis.com/...",
      "wallet_link": "https://www.soundside.ai/auth/wallet-link?token=eyJ...",
      "x402_session_token": "eyJ..."
    }
  }
}
```

Just download from `structuredContent.url`. No additional payment or tool call required.

## Async Resources

Video and music generation are async — they return a `resource_id` immediately but `status: "pending"` (no URL yet).

To check status once the job completes:
```
GET https://mcp.soundside.ai/api/x402/resource/{resource_id}
Header: Authorization: Bearer <x402_session_token>
or:     X-Session-Token: <x402_session_token>
```

To list all your resources:
```
GET https://mcp.soundside.ai/api/x402/resources?limit=50
Header: Authorization: Bearer <x402_session_token>
or:     X-Session-Token: <x402_session_token>
```

## Wallet Link and Polling Token

After a successful tool execution via x402, the response includes both `wallet_link` and `x402_session_token`:

```json
{
  "result": {
    "structuredContent": {
      "resource_id": "abc-123",
      "url": "https://storage.googleapis.com/...",
      "wallet_link": "https://www.soundside.ai/auth/wallet-link?token=eyJ...",
      "x402_session_token": "eyJ..."
    }
  }
}
```

**For agents:** Surface `wallet_link` to the human user. It's a short-lived URL (15-min TTL) that creates a browser session — no password, no wallet extension. The user can then manage their assets at `/library`.

**For async polling:** Retain `x402_session_token` and send it back on `/api/x402/resource*`. This is a server-signed token proving which wallet/project can see the resources. Clients do not generate it. It is also available in the `X-Session-Token` response header. TTL is 1 hour for sync tools, 24 hours for async tools (video, music).

Async tool responses also include `poll_url` and `poll_auth` fields so agents can discover polling endpoints without out-of-band knowledge:

```json
{
  "structuredContent": {
    "resource_id": "abc-123",
    "status": "pending",
    "poll_url": "https://mcp.soundside.ai/api/x402/resource/abc-123",
    "poll_auth": "Bearer <x402_session_token>",
    "x402_session_token": "eyJ...",
    "wallet_link": "https://www.soundside.ai/auth/wallet-link?token=eyJ..."
  }
}
```

## Discovery — Bazaar Extension

When the server returns a 402, the response body includes a `bazaar` field with input/output schema metadata per the [Coinbase CDP Bazaar specification](https://docs.cdp.coinbase.com/x402/bazaar):

```json
{
  "x402Version": 2,
  "accepts": [...],
  "extensions": {
    "bazaar": {
      "info": {
        "input": { "type": "http", "method": "POST", "bodyType": "json", "body": {...} },
        "output": { "type": "json", "example": {"success": true, "resource_id": "..."} }
      },
      "schema": { "$schema": "...", "type": "object", "properties": {...} }
    }
  }
}
```

Agents can use this to pre-validate arguments before signing. The CDP facilitator also catalogs this at `/discovery/resources`.

## Operator Note

If you self-host Soundside MCP:

- `WALLET_LINK_SECRET` signs browser `wallet_link` URLs
- `X402_SESSION_TOKEN_SECRET` signs `x402_session_token` polling tokens
- If `X402_SESSION_TOKEN_SECRET` is unset, the server falls back to `WALLET_LINK_SECRET`

One strong random secret is enough if you want the simpler setup.

## Protocol Details (Manual Implementation)

If you're implementing x402 from scratch instead of using the SDK:

1. **POST** your `tools/call` to `/mcp` — no auth header
2. **Receive 402** with `accepts[0]` containing deposit address, amount, network
3. **Sign** an EIP-3009 `transferWithAuthorization` (off-chain EIP-712, no gas)
4. **Retry** with `payment-signature: <base64(JSON PaymentPayload)>` header
5. **`accepted` field must be an exact copy of `accepts[0]`** — any mismatch fails

See the [x402 protocol spec](https://www.x402.org/) for details.

## Error Reference

| Error | HTTP | Cause | Fix |
|-------|------|-------|-----|
| `Invalid payment signature header` | 402 | Bad encoding, wrong signing method, or stale nonce | Use `x402ClientSync` + `encode_payment_signature_header()` — do not construct manually. Generate a fresh payment per call. |
| `x402_tool_not_enabled` | 403 | Tool/provider not available on x402 lane | Check `/api/x402/status` for enabled tools |
| `x402_provider_not_enabled` | 403 | Provider not supported on x402 | Check status endpoint — use a listed provider |
| `x402_replay_detected` | 402 | Reused payment nonce | Never reuse a `PaymentPayload` — call `create_payment_payload()` fresh each request |
| `x402_settlement_failed` | 402 | Insufficient USDC balance or wrong network | Check balance on Base mainnet (chain 8453); ensure wallet has USDC not ETH |
| `Missing session ID` | 400 | No `mcp-session-id` header | Call `initialize` first and use the returned session ID |
| `Only project owner can list shares` | tool error | Calling `lib_share(list)` as wrong user | Use the same wallet/API key that owns the project |

## Common Mistakes

**1. Constructing the payment header manually**  
The EIP-712 typed data structure, nonce format, and base64 envelope must be exact. Use the SDK.

**2. Forgetting `x402-wallet` header**  
Without it, resources are not attributed to your wallet's project and `wallet_link` / `x402_session_token` won't be returned.

**3. Reusing a payment payload**  
Each `PaymentPayload` has a random nonce. The server detects replays. Call `create_payment_payload()` fresh for every request.

**4. Wrong Python version**  
`x402` requires Python ≥ 3.10. Check with `python3 --version`.

**5. Parsing the 402 body vs header**  
Soundside returns the `PaymentRequired` data in the **response body** (JSON), not in a header. Parse it with `PaymentRequired.model_validate(r.json())`.
